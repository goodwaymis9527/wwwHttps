# 動態網頁搬移 + 批次檔改版紀錄

## 1. 任務

1. `D:\LucaWebVercel`（Next.js 動態網頁）搬到 `D:\goodwaymis9527\LucaWebVercel`。
2. `gitGithubPush.bat` 加上 `LucaWebVercel` 的 push。

## 2. 搬移前的現況

| 項目 | 說明 |
|---|---|
| `D:\LucaWebVercel\.git` | 獨立 repo，remote = `https://github.com/goodwaymis9527/luca-web.git`，分支 `main` |
| 內容 | `app/`、`lib/`、`scripts/`、`neon.ts`、`schema.sql`、`package.json`、`.env.local`、`node_modules/`、`.next/`、`.vercel/` |

## 3. 實際做法（依你的選擇：註冊成 submodule）

1. **搬移**：`Move-Item` 失敗（`D:\LucaWebVercel` 被其他程序鎖住），改用微信 `robocopy /E /MOVE`，
   1254 個檔案全部搬到 `D:\goodwaymis9527\LucaWebVercel`。
2. **註冊 submodule**（不含網路，離線完成）：

   ```powershell
   cd D:\goodwaymis9527
   git config -f .gitmodules submodule.LucaWebVercel.path LucaWebVercel
   git config -f .gitmodules submodule.LucaWebVercel.url https://github.com/goodwaymis9527/luca-web.git
   git add .gitmodules
   git add LucaWebVercel          # 記錄的是 commit 指針（mode 160000），不是檔案內容
   ```

   結果：

   ```
   .gitmodules   mode 100644
   LucaWebVercel mode 160000 → 854aa85 (heads/main)
   ```

3. **意義**：Pages repo 只記住「luca-web 的哪個 commit」，Next.js 的檔案本體仍屬於 luca-web repo。
   這正是 submodule 的設計：`node_modules`、`.next` 不会被 Pages repo 收到，網站也不會被污染。

## 5. `gitGithubPush.bat` 的改寫（保留原註釋與檢查邏輯）

### 改寫原因

- 原本只處理一個 repo，現在要處理兩個，因此把「冲突扫描 → add → commit → push」抽成
  `:PUSH_REPO` 子常式，兩邊共用同一套檢查，行為與原本完全相同。
- **順序是關鍵**：必須先 push submodule，外層 repo 才會記錄到「最新的」commit 指針；
  順序反过来時，外層 commit 記錄的是舊指針，GitHub 上會顯示落後。
- commit 訊息各自專屬：`from Goodway 更新 LucaWebVercel` / `from Goodway 更新 goodwaymis9527`。
- 錯誤處理從 `exit /b` 改成 `exit /b 1`，讓主流程可以用 `if errorlevel 1 goto FAIL` 判斷，
  任何一邊失敗就中止（不會出現「一半已 push、一半失敗」的半完成狀態）。
- 原本的 `git ph` 別名是**全域** alias（`git config --global` 有 `ph = push -u github main`），
  所以在兩個 repo 內都有效，不需要改別名。

### 額外發現：批次檔必須是 CRLF

改寫後我用 dry-run（把 git 指令換成模擬結束碼）跑過一次，第一次 `call :PUSH_REPO` 與 `goto` 都失效，
原因是檔案被寫成 **LF only**；`cmd.exe` 的批次解析在只有 LF 時會把行剪錯（label 與中文一起亂掉）。
把檔案轉成 **CRLF** 後，dry-run 完整跑通兩個 repo 的流程：

```
[Push] luca-web (submodule) → ✔ 已 push
[Push] GitHub Pages          → ✔ 已 push
```

### 新的流程

```
call :PUSH_REPO "D:\goodwaymis9527\LucaWebVercel"  → luca-web (submodule)
call :PUSH_REPO "D:\goodwaymis9527"                → GitHub Pages (wwwHttps)
```

印出的網址：

```
Pages      ：https://goodwaymis9527.github.io/wwwHttps/wwwHttps/
luca-web   ：https://github.com/goodwaymis9527/luca-web
```

## 8. 404 的排查與修正

### 現象

`https://goodwaymis9527.github.io/wwwHttps/` → 404。

### 原因

GitHub Pages 把 **repo 根目錄** 對應到 `/{repo}/`。搬移後根目錄沒有 `index.html`
（只剩 `.nojekyll`、批次檔、紀錄資料夾），網站本體在 `wwwHttps/` 子資料夾，
所以實際可用的網址是 `https://goodwaymis9527.github.io/wwwHttps/wwwHttps/`（實測 200）。

GitHub 上 `main` 的 tree（實測）：

```
.gitmodules
.nojekyll
20261105_靜態網頁搬移_OpenCode/     ← 紀錄檔被 commit 進去（已被 gitignore，但歷史還在）
20261105_動態網頁搬移_OpenCode/
LucaWebVercel                        ← mode 160000（submodule 指針）
gitGithubPush.bat
opencode.json                        ← ⚠️ API key 公開
wwwHttps/index.html
```

### 修正動作

1. 在 repo 根目錄新增轉送用的 `index.html`（`meta http-equiv="refresh" content="0; url=wwwHttps/"`）。
   GitHub Pages 沒有伺服器端 301/302，只能用 meta refresh；頁面上同時給了手動連結備援。
   → `https://goodwaymis9527.github.io/wwwHttps/` 恢復可用。
2. `git rm --cached opencode.json` + 新增 `.gitignore`（`opencode.json`、`*_OpenCode/`）。
   **舊 commit 仍在 GitHub，API key 必須手動撤銷。**
3. `gitGithubPush.bat` 的網址列改回根網址，並加註解說明根頁是轉送頁。

## 9. 核心觀點總結

1. 同一工作目錄只能屬一個 repo；跨 repo 共處的正解是 submodule 或 .gitignore。
2. `git add` 內嵌 repo 只會產生 gitlink（commit 指針），檔案本體不會進外層 repo。
3. submodule 的 push 順序：先內層、後外層，外層記錄的指針才會是最新的。
4. `robocopy /E /MOVE` 是資料夾被鎖住時比 `Move-Item` 更穩的搬移方式。
5. 批次檔抽出子常式後，檢查邏輯（衝突掃描、no-change 判斷）只需寫一次，兩 repo 行為一致。
6. 被追蹤的設定檔（含 API key）比目錄結構更容易出事，push 前要確認。
7. GitHub Pages 的 `/{repo}/` 永遠對應 repo 根目錄；網站放在子資料夾就必然多一層路徑，
   要嘛把檔案放根目錄，要嘛在根目錄放轉送頁（Pages 沒有伺服器端 redirect）。
8. `git rm --cached` 只能停止追蹤，已推上公開 repo 的檔案與歷史要靠撤銷憑據（key）來止血。
