# 靜態網頁搬移紀錄

## 1. 任務
將原本位於 `D:\goodwaymis9527`（repo 根目錄）的靜態網頁，搬移到
`D:\goodwaymis9527\wwwHttps`。

## 2. 搬移前的現況

| 檔案 | 位置 | 說明 |
|---|---|---|
| `index.html` | repo 根目錄 | 靜態網頁本體（Hello World） |
| `.nojekyll` | repo 根目錄 | 告訴 GitHub Pages 跳過 Jekyll 處理 |
| `gitGithubPush.bat` | repo 根目錄 | commit + push 到 GitHub 的批次檔 |
| `opencode.json` | repo 根目錄 | OpenCode 設定（未納入 git，`??` 未追蹤） |

Git 遠端：`github → https://github.com/goodwaymis9527/wwwHttps.git`，分支 `main`。

## 3. 執行的動作

1. 建立資料夾：`D:\goodwaymis9527\wwwHttps`
2. 用 `git mv` 搬移（保留 git 歷史，比單純檔案移動更好）：

   ```powershell
   git -C D:\goodwaymis9527 mv index.html wwwHttps/index.html
   ```

3. 結果：

   ```
   R  index.html -> wwwHttps/index.html
   ?? opencode.json
   ```

## 4. 刻意保留在根目錄的檔案

- `.nojekyll`：GitHub Pages 判斷是否跳過 Jekyll 是看 **repo 根目錄** 的
  `.nojekyll`，移到子資料夾會失效，所以留在根目錄。
- `gitGithubPush.bat`：是工具腳本，不是網頁內容，留在根目錄。

## 5. ⚠️ 需要注意的重點：URL 會改變

因為 **repo 名稱就叫 `wwwHttps`**，GitHub Pages 的網址目前是：

```
https://goodwaymis9527.github.io/wwwHttps/          ← repo 根目錄的 index.html
```

搬移後 `index.html` 位於 repo 內的 `wwwHttps/` 子目錄，網址變成：

```
https://goodwaymis9527.github.io/wwwHttps/wwwHttps/index.html
```

也就是 `gitGithubPush.bat` 第 80 行印出的網址會失效（多了一層 `wwwHttps/`）。

### 三個可行方案

1. **✅ 已選用：維持現況 + 改網址**——把 `gitGithubPush.bat` 的提示網址改成
   `https://goodwaymis9527.github.io/wwwHttps/wwwHttps/`。最省事，但網址多一層。
2. **改 repo 名稱**：在 GitHub 把 repo 改名（例如 `pages` 或 `goodwaymis9527.github.io`），
   再更新 remote URL，子資料夾名稱就不會重複。
3. **只留本地結構**：`wwwHttps` 只是本地整理用的資料夾，那就要另外設定部署來源
   （GitHub Pages 的 `source: main branch` 讀的是根目錄，需搭配 Actions 或自架 Apache/Nginx 的 DocumentRoot）。

### 本輪實際修改

- `gitGithubPush.bat` 第 80 行：

  ```diff
  - echo ✔ GitHub 上線約 1 分鐘：https://goodwaymis9527.github.io/wwwHttps/
  + echo ✔ GitHub 上線約 1 分鐘：https://goodwaymis9527.github.io/wwwHttps/wwwHttps/
  ```

  原因：`index.html` 現在位於 repo 內的 `wwwHttps/` 子目錄，而 repo 本身也叫 `wwwHttps`，
  GitHub Pages 的網址會多一層路徑；批次檔的提示訊息必須與實際網址一致，否則 push 後點連結會 404。

## 6. 後續步驟


注意：`git add .` 也會把本紀錄資料夾
`20261105_靜態網頁搬移_OpenCode` 一起 commit 進 repo；
如果不希望它出現在网站上，可加入 `.gitignore` 或移到 repo 外。

## 7. 核心觀點總結

1. 用 `git mv` 而非檔案剪貼，歷史追蹤才完整。
2. `.nojekyll` 必須留在 repo 根目錄，不能跟著網頁一起搬。
3. 靜態網站的 URL 取決於「repo 名稱 + 檔案在 repo 內的路徑」，兩者同名會產生重複路徑。
4. 工具檔（批次檔）與內容檔（html）分開放，是較好的目錄結構。
5. 部署前確認 `git status`，避免把設定檔（`opencode.json`，含 API key）誤推到公開 repo。
